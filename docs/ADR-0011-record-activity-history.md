# ADR-0011: 기록 변경 이력을 본문과 같은 트랜잭션으로 저장한다

## 상태

채택. 0.11.0에 구현한다.

## 배경

현재 버전과 생성·확인·공개 시각만으로는 초안 수정, 확인 취소, 폐기와 대체의 처리 시점을 확인할 수 없다. 작업 횟수 지표와 GitHub 게시 시도 이력도 이 정보를 대신하지 못한다.

## 결정

- Flyway V11의 `record_activities`에 기록 ID, 작업 종류, 인증 사용자의 숫자 ID 기반 subject, 이전·이후 버전과 상태, 처리 시각만 저장한다. 본문·대화·검증 출력·자격 증명은 복제하지 않는다.
- 작업은 `CREATE`, `REVISE`, `CONFIRM`, `REOPEN`, `PUBLISH`, `DISCARD`, `SUPERSEDE`로 구분한다. 기존 도메인 상태 전이를 통과한 애플리케이션 서비스가 작업 정보를 만든다.
- JDBC 기록 저장 트랜잭션 안에서 이력을 추가한다. 이력 저장은 기존 트랜잭션이 있어야 실행할 수 있다. 기록 저장이나 이력 저장 중 하나가 실패하면 둘 다 취소한다.
- `(record_id, version)`을 기본 키로 사용한다. 버전 충돌·동일 생성 요청의 재시도는 성공 이력을 추가하지 않는다. GitHub 원격 호출은 이 트랜잭션에 포함하지 않는다.
- 생성 이전 이력을 추정하거나 기존 기록에 소급해서 추가하지 않는다. 작성자 조회의 `historyStartsAtCreation=false`로 수집 이전 작업을 확인할 수 없음을 알린다.
- REST·MCP·브라우저가 같은 `RecordActivityService`를 사용한다. 기록 읽기 권한을 먼저 확인한 뒤 작성자는 전체 작업, 다른 팀원은 `PUBLISH`·`SUPERSEDE`만 조회한다. 비공개 기록의 이력은 작성자만 읽는다.
- 결과는 버전 내림차순으로 50개씩 반환한다. 다음 페이지는 `nextBeforeVersion`을 사용한다. 팀 조회에는 비공개 작업을 페이지 조회 전에 제외하고 `historyStartsAtCreation`은 null로 반환한다.
- 이력을 수정·삭제하는 제품 API는 제공하지 않는다. 초안 폐기는 상태 변경이며 기존 기록과 이력을 삭제하지 않는다. 보존 기간과 운영자 삭제 정책은 별도 결정으로 남긴다.

## 영향

제품 데이터이므로 기존 PostgreSQL backup·restore에 포함한다. 사용자 token·세션의 메모리 전용 정책은 유지한다. 과거 본문의 복원이나 제3자의 실행 증명은 제공하지 않는다. 기존 공개 기록을 읽을 수 있는 팀원에게 과거 초안 작업을 자동 공개하지 않는다.
