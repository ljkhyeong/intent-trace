# PRD-0005: 내 기록함과 파일별 이력 조회

## 목표

기록 UUID를 몰라도 저장소의 공개 의도와 내 비공개 초안을 찾는다. 현재 커밋의 줄 조회 결과가 없을 때 같은 파일에 남긴 다른 커밋의 기록을 찾아 원래 코드와 검증을 확인한다.

## 조회 계약

- REST: `GET /api/v1/change-records`
- MCP: `list_change_records`
- 공통 입력: 필수 `repositoryKey`, 선택 `scope`, `path`, `status`, `page`, `size`
- `repositoryKey`는 기존과 같이 소문자 `owner/repository`로 정규화한다. 요청마다 해당 저장소의 읽기 권한을 확인한다.
- 기본 `scope=TEAM`은 `PUBLISHED`, `SUPERSEDED`를 조회한다.
- `scope=MY_DRAFTS`는 인증된 숫자 GitHub 사용자 ID로 만든 `DRAFT`, `AUTHOR_CONFIRMED`만 조회한다. 작성자 입력은 받지 않는다.
- `status`를 지정하면 선택한 기록함에서 해당 상태만 조회한다. 다른 기록함의 상태는 입력 오류다.
- `path`를 지정하면 기존 상대 경로 정규화를 거쳐 코드 근거의 경로와 정확히 비교한다. 커밋과 줄 번호는 필터링하지 않는다.
- `page`는 0부터, `size`는 기본 20·최대 50이다. 0 이하 크기와 음수 페이지는 입력 오류다.
- 생성 시각 내림차순, 같은 시각이면 기록 UUID 내림차순으로 정렬한다. 생성 시각은 공개 시각과 다르다.
- 응답은 `items`, `page`, `size`, `hasNext`다. 총 건수 조회는 하지 않는다.
- 요약에는 ID, 저장소, 제목, 상태, 전체 커밋, 작성자, 생성·공개 시각, 대체 기록 ID를 포함한다. 본문·근거·검증은 기존 단건 조회로 읽는다.

권한과 파일·상태 필터는 페이지를 자르기 전에 SQL에서 적용한다. 다른 사람의 초안은 본문뿐 아니라 `hasNext`에도 영향을 주지 않는다. 목록을 본 뒤 상세를 열 때도 권한을 다시 확인한다.

## IntelliJ 흐름

1. GitHub remote가 있는 저장소의 파일을 선택하고 `IntentTrace 기록함 열기`를 실행한다.
2. 팀 공개 기록 또는 내 비공개 기록과 상태를 고른다. 필요하면 `현재 파일만`을 선택하고 `조회`한다.
3. 이전·다음 페이지로 이동하고 `선택 기록 열기`로 상세를 읽는다.
4. `원래 커밋 열기`와 `당시 코드 열기`는 전체 커밋 SHA에 고정한 GitHub 페이지를 시스템 브라우저로 연다. 코드 링크는 기록에 저장된 줄 범위를 사용한다.
5. 대체된 기록은 `대체 기록 열기`로 직접 후속 기록을 연다. 후속 기록도 대체됐으면 사용자가 계속 따라갈 수 있다.
6. 현재 줄 조회 결과가 없으면 `이 파일의 과거 기록 보기`를 선택할 수 있다. 자동으로 현재 줄의 의도라고 연결하지 않는다.

내 비공개 초안은 커밋이 아직 없을 수 있다. 이 경우 커밋·코드 이동 버튼을 비활성화한다. IntelliJ의 HTTP·PasswordSafe 접근은 UI thread 밖에서 실행하며, 기존 token·timeout·redirect·응답 크기 제한을 유지한다.

조회에 실패하면 오류를 안내하고 필터와 `현재 파일만` 선택을 마지막 성공 조건으로 되돌린다. 기존 목록·선택·페이지는 유지하며, 재조회에 성공한 경우에만 새 조건과 결과를 함께 적용한다.

## 과거 기록의 의미

- 과거 이력은 커밋되지 않은 파일에서도 조회할 수 있지만, 현재 줄 조회의 변경 파일 거부 규칙은 유지한다.
- `verifications.current`는 **기록에 저장된 스냅샷과의 일치**다. 현재 IDE 코드가 검증됐다는 뜻이 아니다. 두 화면 모두 이 의미를 표시하고 과거 상세에는 별도 안내를 붙인다.
- 파일 이름 변경·이동 전 경로는 자동 추정하지 않는다. 필요하면 저장소 전체 목록에서 찾는다.
- 페이지는 조회 시점의 데이터다. 중간에 기록을 생성·공개하면 페이지 구성이 달라질 수 있으며 고정된 검색 스냅샷을 보장하지 않는다.

## 이번 범위에서 제외

- 초안 수정·삭제, 자동 기록 생성과 AI 요약 확정
- 파일 rename·줄 이동 자동 추적
- 전체 저장소를 한 번에 모으는 개인 대시보드, 전문 검색과 총 건수
- IntelliJ ToolWindow 재설계, 코드 본문·대화 원문 수집

## 검증 기준

- REST 인증 사용자가 다른 작성자의 초안과 권한 없는 저장소를 조회할 수 없다.
- 같은 파일의 여러 코드 근거가 있어도 기록을 중복 반환하지 않는다.
- H2와 PostgreSQL에서 상태·파일·작성자 필터, 같은 시각의 페이지 정렬, 마지막 페이지와 대체 연결이 일치한다.
- MCP에서 선택 인자를 생략하면 기본 페이지를 조회한다.
- IntelliJ가 목록·상세에 같은 세션을 사용하고 과거 검증을 현재 코드 검증으로 표시하지 않는다.
- IntelliJ 목록 조회가 실패하면 마지막 성공 조건과 목록·선택·페이지를 유지하고, 재조회 성공 시 새 조건을 적용한다.
- 공백·한글·`#`·`?`가 있는 파일 링크도 경로로 인코딩하며 원래 전체 커밋을 벗어나지 않는다.
