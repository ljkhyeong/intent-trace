## 실행 결과

- `./gradlew test`: 90개 중 89개 통과, 실패 0개. PostgreSQL 전용 1개는 기본 실행에서 제외했다.
- `scripts/verify-postgres.sh`: 별도 임시 PostgreSQL 17에서 migration·JDBC·backup·restore 통과. 변경 기록 2건과 이력 4건이 복구 전후 일치했다.
- `npm ci --prefix clients/zed --ignore-scripts`: 고정 의존성 설치 성공, 알려진 취약점 0개.
- `npm test --prefix clients/zed`: 8개 통과. HTTP 401·403·429·502 분류, 초기 `check` 실패의 대기 시간, 외부 응답에 담긴 합성 token 미노출, 대기 시간 형식을 확인했다.
- `ZedBridgeIntegrationTest`: 표준 stdio SDK와 실제 Spring 서버의 연결·도구 목록·진단 호출 통과. 서버 MCP 도구는 24개다.
- 새 `list_record_activities`는 실제 MCP 요청에서 선택 `beforeVersion` 생략과 이력 반환을 확인했다.
- 플러그인 구조와 사용·개발 스킬 형식 검증 통과.

이력 테스트는 성공한 작업의 버전, 생성 재시도·충돌의 중복 방지, 이력 저장 실패 시 본문 롤백, 50개 페이지 연결, 수집 이전 이력 표시, 작성자·팀 권한을 확인했다. 웹 테스트는 다른 사용자의 연결 종료 차단, Origin 검사, 현재 연결 cookie 제거, 비공개 기록의 조회·이력 차단, 일부 실패 재조회와 세부 비교를 확인했다.

## 브라우저 확인

통합 테스트가 실제 화면 렌더러로 생성한 HTML을 로컬에서 제공하고 Chromium에서 확인했다. 파일·줄 조회, 원본 비교, 내 연결 목록을 390×844에서 확인했으며 문서 너비 375px로 가로 넘침이 없었다. 캡처는 로컬 `output/playwright/v11-history-mobile.png`, `v11-comparison-mobile.png`, `v11-sessions-mobile.png`에 남겼다. 캡처는 저장소에 커밋하지 않는다.

화면 이동·인증·데이터 처리는 서버 통합 테스트로 확인했다. 실제 브라우저에서 GitHub 로그인과 연결 종료까지 다시 수행한 결과는 아니다.

## 검증 한계

- 외부 GitHub 사용자 승인이나 실제 저장소의 Check Run 게시는 수행하지 않았다.
- 실제 Zed 앱 검증은 0.10.0 기록을 유지한다. 0.11.0 오류 처리는 로컬 응답·표준 SDK·실제 Spring 서버로 검증했다.
- 이력은 작업 메타데이터이며 과거 본문이나 수집 시작 전 작업을 복원하지 않는다. 단일 인스턴스·메모리 세션·코드 근거 크기 제한은 유지한다.
