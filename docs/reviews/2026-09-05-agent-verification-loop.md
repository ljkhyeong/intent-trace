# 에이전트 검증 반복 점검

## 확인 범위

IntentTrace의 기존 작업 `검토할 기능 개선점 찾기`에서 최근 문구 수정 두 건과 `Find Baton toy project ideas`에서 OAuth 검증·병합 작업을 확인했다. 작업 기록의 명령·종료 상태·변경 파일과 현재 Gradle·검증 스크립트를 대조했다. 전체 세션 통계나 절감 시간 측정은 아니다.

## 확인한 문제와 변경

| 확인한 사실 | 반복을 줄이는 변경 |
| --- | --- |
| 0.12.2·0.12.3 문구 수정에서 전체 서버 테스트를 각각 두 번 실행했고, 사이에 코드·스타일을 추가 수정했다. 재실행은 변경 때문에 필요했다. | 관련 테스트는 편집 중, 전체 테스트는 코드·문구·기대값 수정을 마친 뒤 실행한다. |
| 같은 `test` 작업에 `--tests` 필터를 바꾸고 PostgreSQL 검증도 실행했다. 결과 디렉터리를 공유했다. | `focusedTest`·`test`·`postgresTest`로 나눠 전체 결과와 증분 실행 상태를 보존한다. |
| 테스트 수 집계용 XML 파싱 코드를 작업마다 다시 작성했다. | `scripts/test-summary.py`로 결과를 읽고 실패·오류·건너뜀을 구분한다. |
| Gradle에 `git-evidence.sh`만 외부 입력으로 등록돼 있었다. 실행하는 Python·Zed 파일 변경은 입력에 없었다. | 검증 스크립트·Zed 실행 파일·의존성 명세·SDK 설치 여부를 입력에 추가한다. |
| 존재하지 않는 테스트 경로를 지정한 조회 실패가 있었고, 산출물 손상 복구 뒤 후속 작업에서도 `clean test`를 사용했다. | 파일 목록으로 경로를 찾고, 산출물 손상이나 환경 문제가 확인된 경우에만 복구 옵션을 사용한다. |
| OAuth 검증에서 브라우저와 셸의 클립보드가 공유되지 않아 자격 증명 전달에 실패했다. | 비밀값 재발급보다 실패 단계·전달 경로 확인을 먼저 한다. |
| 이번 PostgreSQL 검증에서 고정 포트 55432가 사용 중이라 시작하지 못했다. | Docker가 빈 로컬 포트를 배정하고 스크립트가 실제 매핑을 조회한다. 기존 고정 포트 설정은 선택값으로 유지한다. |

이전 문구 수정의 범위·결과는 [0.12.2 검증](2026-09-05-v0.12.2-verification.md), [0.12.3 검증](2026-09-05-v0.12.3-verification.md)에 남아 있다. 이후 절차는 [로컬 검증과 작업 재개](../development/verification.md)를 따른다.

CI의 전체 서버·IntelliJ·PostgreSQL 검사는 유지한다. 이번 변경은 로컬 실행 순서와 테스트 결과 보존을 개선하며, 과거 성공을 현재 코드의 검증으로 자동 처리하지 않는다.

## 이번 검증

- 서버 전체 165개, 부분 실행한 수명주기 테스트 9개, 별도 PostgreSQL 테스트 4개가 통과했다. 부분 테스트 9개는 전체 165개에 포함되므로 합산하지 않는다.
- 새 PostgreSQL에서 백업·복구 후 기록 13건·변경 이력 28건이 유지됐다. 처음에는 기존 고정 포트가 사용 중이어서 시작하지 못했고, 자동 배정 방식으로 수정한 뒤 통과했다.
- 부분·PostgreSQL 검증 전후 서버 XML 결과의 SHA-256이 같았다. 이어서 `./gradlew test`를 호출했을 때 `:test UP-TO-DATE`, 작업 5개 모두 재사용으로 끝나 테스트를 다시 실행하지 않았다.
- 결과 집계 도구 테스트 3개, 플러그인·변경한 개발 스킬 검사와 셸 구문 검사를 통과했다.
- IntelliJ·Zed 구현과 제품 API는 바꾸지 않았다. IntelliJ·Zed 단독 테스트, 실제 IDE·GitHub 게시와 원격 CI는 이번 검증에 포함하지 않았다. Zed와 실제 서버 연결은 서버 전체 테스트에 포함됐다.
