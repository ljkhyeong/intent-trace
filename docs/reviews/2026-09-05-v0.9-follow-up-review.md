# IntentTrace 0.9.0 이후 개선 검토

검토일: 2026-09-05  
기준 커밋: `7ebf9b66e6619ec631e17247ee58a364436f785b`  
상태: 코드와 외부 계약을 확인한 제안. 아래 항목을 새 요구사항이나 구현 완료로 취급하지 않는다.

## 우선순위

| 순서 | 우선순위 | 항목 | 필요한 결과 |
|---|---|---|---|
| 1 | P1 | 새 GitHub 설치 토큰 전체 제거 | 설명에 들어온 JWT 형식 토큰의 점 뒤 내용까지 제거한다. |
| 2 | P1 | 같은 요청의 GitHub 조회 중복 제거 | 저장소 권한과 같은 커밋 객체를 한 요청 안에서 재사용한다. |
| 3 | P1 | 과거 기록 조회의 일부 실패 표시 | 한 후보의 지원하지 않는 파일 때문에 전체 목록을 잃지 않는다. |
| 4 | P1 | 게시 자격 증명 사전 점검 | 설정 존재·키 유효성·설치·부여 권한을 구분한다. |
| 5 | P2 | 원본과 후속 초안 비교 | 바뀐 판단·코드 근거·검증·남은 질문을 확인 전에 읽는다. |
| 6 | P2 | 브라우저 PR 목록과 진단 화면 | 이미 있는 REST·MCP 조회를 팀원이 브라우저에서도 사용한다. |
| 7 | P2 | Zed 설정 등록과 실제 앱 검증 | 설정 추가·업데이트를 안내하고 재연결까지 앱에서 확인한다. |

P1부터 작은 변경으로 진행하고, P2는 실제 사용 흐름에 맞춰 이어간다. 이번 우선순위는 운영 부하 측정 결과가 아닌 코드와 사용 절차에 근거한 판단이다.

## 1. 새 GitHub 설치 토큰 전체 제거

[서버 비밀값 제거](../../src/main/kotlin/io/intenttrace/record/application/SensitiveTextRedactor.kt)와 [로컬 검증 수집 도구](../../scripts/run-verification.py)의 알려진 토큰 정규식에는 점이 없다. GitHub는 점 두 개를 포함하는 `ghs_` JWT 형식을 안내한다. [GitHub 변경 안내](https://github.blog/changelog/2026-05-15-github-app-installation-tokens-per-request-override-header/)

Bearer 헤더나 `token=` 대입문은 별도 규칙으로 제거되지만 일반 설명 속 단독 토큰은 앞부분만 제거될 수 있다. 실제 자격 증명이 아닌 합성 문자열로 Python `redact`를 실행해 점 뒤 두 구간이 남는 것을 확인했다. Kotlin 규칙에서도 같은 문자 누락을 확인했으며 JVM 재현 테스트는 이번 검토에서 추가하지 않았다.

완료 기준은 두 구현에서 기존 토큰·JWT 형식 전체가 제거되고 문장 경계가 유지되는 것이다. 실제 token을 테스트·문서·로그에 넣지 않는다. 기존 저장 데이터에 해당 값이 존재하는지는 확인하지 않았다.

## 2. 같은 요청의 GitHub 조회 중복 제거

[RepositoryAccessService](../../src/main/kotlin/io/intenttrace/identity/application/GitHubUserAccess.kt)는 호출마다 저장소 권한을 다시 읽는다. [PR 목록](../../src/main/kotlin/io/intenttrace/publication/application/PullRequestOverviewService.kt)과 [이전 기록 조회](../../src/main/kotlin/io/intenttrace/record/application/ChangeIntentHistoryService.kt)는 먼저 읽기 권한을 확인하고 카탈로그 목록에서도 다시 확인한다. 진단도 읽기·쓰기 권한을 각각 조회한다. 이전 기록 조회의 객체 캐시는 후보 기록마다 초기화된다.

최소 범위는 동일한 인증 요청 안의 숫자 사용자 ID·정규화 저장소별 권한 재사용과 제한된 Git 객체 캐시다. 새 요청에서는 다시 권한을 확인한다. 요청 간 권한 캐시는 별도 계약으로 남긴다. 호출 수를 테스트로 확인하며 실제 속도 개선 폭은 측정 후 보고한다. 호출 제한 시 대기 규칙은 [GitHub API 권장 사용법](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)을 유지한다.

## 3. 과거 기록 조회의 일부 실패 표시

현재 history는 후보의 GitHub 트리·blob 조회가 예외를 던지면 전체 요청이 실패한다. 지원 크기를 넘는 파일 하나가 포함된 경우에도 다른 후보의 결과를 반환할 수 없다.

후보별로 확인한 결과와 확인하지 못한 이유를 구분하고 응답의 불완전 여부를 표시한다. 인증 실패·권한 회수·호출 제한은 정상 결과처럼 숨기지 않는다. 호출 제한은 추가 요청을 멈추고 기존 대기 계약을 유지한다. 실패 후보를 커서만 진행해 영구적으로 놓치지 않도록 재조회 방법도 제공한다.

## 4. 게시 자격 증명 사전 점검

[현재 진단](../../src/main/kotlin/io/intenttrace/connection/application/ConnectionDiagnostics.kt)은 서버 설정 문자열의 존재만 확인한다. [설치 token 발급 어댑터](../../src/main/kotlin/io/intenttrace/publication/adapter/out/github/GitHubAppInstallationClient.kt)는 게시 시 설치를 조회하고 필요한 권한으로 token을 발급하지만 응답의 부여 권한은 보존하지 않는다.

운영자가 요청하는 사전 점검에서 키 사용 가능 여부, 대상 설치, 저장소 범위와 부여 권한을 확인한다. 필요한 경우 메모리에서 installation token을 발급하며 Check Run은 생성하지 않는다. 설정만 확인한 결과와 원격 발급·조회로 확인한 결과를 구분한다. GitHub는 발급 응답에 token 권한과 해당되는 저장소 범위를 포함한다고 설명한다. [GitHub installation token 문서](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)

## 5. 원본과 후속 초안 비교

현재 후속 초안은 원본 링크를 제공하지만 두 기록의 내용 차이를 계산하지 않는다. 작성자가 복사한 판단을 고친 뒤 확인할 때 원본과 새 내용을 나란히 비교할 수 있으면 도움이 된다.

읽기 전용 비교 사용 사례에서 판단·출처·코드 근거·검증·질문을 비교한다. 후속 초안은 본인만 읽고 원본 공개 본문은 변경하지 않는다. 새 검증이 없는 사실과 삭제한 근거를 명확히 표시한다.

## 6. 브라우저 PR 목록과 진단 화면

[기록 브라우저](../../src/main/kotlin/io/intenttrace/record/adapter/in/browser/RecordBrowserController.kt)는 기록 목록·검색·단건 열람을 제공한다. PR별 기록과 연결 진단은 REST·MCP에 있다.

기존 읽기 사용 사례를 브라우저에서 호출해 PR 커밋과 맞지 않는 기록, 게시 결과 미확인, 연결 실패 항목을 표시한다. 브라우저 전용 세션과 로그인 복귀 경로를 필요한 화면에만 확장한다. 공개·게시 등 쓰기 작업을 이 화면에 자동으로 추가하지 않는다.

## 7. Zed 설정 등록과 실제 앱 검증

[연결 도구](../../clients/zed/intent-trace.mjs)는 설정 JSON을 출력하고 사용자가 Zed 설정에 붙여 넣는다. [실행 도구](../../scripts/zed-with-intent-trace.py)는 세션을 숨겨 입력받는다. 실제 Spring 서버와 중계기 연결은 검증했지만 Zed 앱의 설정·도구 승인·재연결은 아직 확인하지 않았다.

등록 도구는 기존 JSONC 설정과 다른 MCP 서버를 보존하고 변경할 부분을 먼저 보여준다. token은 계속 환경 변수로만 전달한다. 설치·업데이트·중복 등록·Node 경로 변경을 처리하고 실제 앱에서 기록 조회와 세션 만료 후 재연결을 확인한다. 도구 승인은 [Zed MCP 설정](https://zed.dev/docs/ai/mcp)의 현재 동작을 따른다.

## 이번 검토 범위

코드·계약·공식 문서를 읽고 합성 값으로 비밀값 제거 문제를 재현했다. 운영 데이터 조회, 실제 GitHub 쓰기, Zed 설치와 기능 구현은 하지 않았다. 실행 코드와 테스트를 변경하지 않아 전체 테스트는 재실행하지 않았다.
