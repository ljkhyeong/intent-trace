# IntentTrace 0.10.0 이후 개선 검토

검토일: 2026-09-05

기준 커밋: `965ffdaf1b4b8fba7a9d24af14cf3aaf1f00351c`

상태: 확인한 오류와 후속 기능 제안. 아래 기능은 아직 구현하지 않았다.

0.9.0 검토의 7개 항목은 0.10.0에 반영됐다. 이번 검토는 남은 연결 오류 처리와 팀원의 조회·관리 흐름에 집중한다. 우선순위는 코드와 로컬 재현에 근거하며 운영 사용량을 측정한 결과는 아니다.

## 우선순위

| 순서 | 우선순위 | 항목 | 필요한 결과 |
|---|---|---|---|
| 1 | P1 | Zed 오류 구분과 대기 시간 전달 | 재로그인, 호출 제한 대기, 서버 장애를 구분한다. |
| 2 | P2 | 웹에서 파일·줄로 기록 찾기와 코드 근거 확인 | 기존 조회 서비스를 화면에서 사용하고 부분 실패도 확인한다. |
| 3 | P2 | 웹에서 내 연결 조회·폐기 | 현재 연결과 다른 연결의 사용 시각·만료를 보고 선택해 종료한다. |
| 4 | P2 | 비교 화면의 세부 변경 표시 | 추가·삭제·출처 변경·순서 변경을 쉽게 찾는다. |
| 5 | P3 | 기록 상태 변경 이력 | 수정·확인 취소·폐기·대체를 누가 언제 처리했는지 남긴다. |

1번을 먼저 수정하고, 기존 서비스를 재사용하는 2·3번을 이어가는 순서를 권한다. 4번은 긴 기록의 검토 편의, 5번은 팀 운영 이력에 필요한 별도 확장이다.

## 1. Zed 오류 구분과 대기 시간 전달

[중계기](../../clients/zed/bridge.mjs)의 `forward`는 원격 호출 예외를 모두 같은 `InternalError`로 바꾼다. [서버 인증 필터](../../src/main/kotlin/io/intenttrace/identity/adapter/in/web/GitHubUserAuthenticationFilter.kt)는 사용자 인증 실패를 401, 호출 제한을 429와 `Retry-After`, 인증 서비스 장애를 502로 구분한다. 이 정보가 중계기 이후에는 사라진다.

로컬 HTTP 응답 서버와 실제 중계기를 표준 MCP SDK로 연결했다. 초기화를 성공시킨 뒤 도구 호출에 아래 응답을 차례로 반환했다.

| 원격 HTTP 응답 | 중계기 뒤에서 받은 결과 |
|---|---|
| 401 | MCP `-32603`, 연결·세션 확인이라는 공통 메시지, 추가 데이터 없음 |
| 429, `Retry-After: 120` | 같은 오류. 120초 대기 정보 없음 |
| 502 | 같은 오류. 사용자 인증 실패와 구분 불가 |

이 재현은 HTTP 전송 오류 경로에 한정한다. 서버 도구가 정상 MCP 응답의 `isError`로 반환한 모든 업무 오류가 사라진다는 의미는 아니다. Zed는 MCP 도구 오류를 Agent에 전달하므로, 중계기가 안전한 원인을 보존해야 사용자가 다음 행동을 정할 수 있다. [Zed 오류 처리 문서](https://zed.dev/docs/ai/mcp)

완료 기준:

- 401은 재로그인 필요, 429는 호출 제한과 정해진 대기 시간, 502는 서버의 외부 연동 장애로 구분한다.
- 응답 헤더의 대기 시간을 형식·범위 확인 후 전달한다. 외부 오류 본문이나 인증 헤더를 그대로 출력하지 않는다.
- 연결 초기화와 연결 후 도구 호출의 두 실패 경로에 같은 분류를 적용한다.
- 시간 초과·응답 유실이 발생한 변경 요청은 기록 또는 게시 상태를 먼저 조회하도록 안내한다. 분류 개선을 이유로 변경 요청을 자동 재실행하지 않는다.
- 로컬 응답을 사용하는 최소 회귀 테스트로 분류·대기 시간·비밀값 미노출을 확인한다.

## 2. 웹에서 파일·줄로 기록 찾기와 코드 근거 확인

[브라우저 컨트롤러](../../src/main/kotlin/io/intenttrace/record/adapter/in/browser/RecordBrowserController.kt)에는 목록·단건·비교·PR·진단 화면이 있다. 파일·줄 기반 조회와 개별 기록의 코드 해시 확인은 [기존 API](../../src/main/kotlin/io/intenttrace/record/adapter/in/web/RecordEvidenceController.kt)에 있다. 현재 기록 화면은 GitHub 코드 링크를 제공하고 서버 확인은 별도 요청이라고 안내한다.

웹에서 저장소·전체 커밋·파일·줄을 입력해 변경 의도를 찾고, 기록 화면에서 필요한 경우 코드 근거를 확인하도록 한다. `ChangeIntentHistoryService`와 `RecordEvidenceService`를 재사용한다.

완료 기준:

- 같은 커밋의 기록, 과거의 동일 코드·이동한 줄, 현재 코드 일치를 확인하지 못한 후보를 구분한다.
- 결과가 없어도 다음 후보 페이지가 있으면 계속 조회할 수 있다. 실패 후보와 사유, 해당 기록 재조회도 제공한다.
- 근거 확인 결과에 기록 버전·커밋·스냅샷·확인 시각을 표시한다. 코드 해시 일치를 테스트 실행 확인으로 표현하지 않는다.
- GitHub 객체 조회는 사용자가 요청할 때 실행한다. 기존 기록 열람마다 추가 원격 확인을 강제하지 않는다.
- 브라우저 전용 세션과 기록 접근 권한을 유지하고 필요한 로그인 복귀 경로만 추가한다.

## 3. 웹에서 내 연결 조회·폐기

[MySessionService](../../src/main/kotlin/io/intenttrace/identity/application/UserSessionManagement.kt)는 본인 연결의 생성·최근 사용·만료 시각, 현재 연결 여부와 선택·전체 폐기를 지원한다. 현재 브라우저에는 자기 브라우저 연결을 종료하는 로그아웃만 있다. 여러 연결 중 정리할 대상을 고르려면 REST 또는 Agent를 사용해야 한다.

웹에 내 연결 목록과 선택 종료를 추가한다. 현재 메타데이터의 채널은 `CLIENT`·`BROWSER` 두 종류다. 이를 근거 없이 특정 Zed·Codex 기기명으로 표시하지 않는다. 연결을 쉽게 구분하려면 사용자가 정하는 짧은 표시 이름을 별도로 추가할 수 있다.

완료 기준:

- 현재 연결을 눈에 띄게 표시하고 선택한 본인 연결만 폐기한다. 전체 종료의 영향도 화면에서 알 수 있다.
- 현재 브라우저 연결까지 폐기하면 cookie를 지우고 로그인 화면으로 이동한다.
- 기존 숫자 사용자 ID 기반 소유권과 갱신 중 폐기 규칙을 재사용한다.
- 연결 관리용 POST에 동일 출처 검사를 적용한다. 브라우저 cookie를 REST·MCP 인증으로 확대하지 않는다.
- ADR-0009의 브라우저 변경 동작 범위를 연결 관리까지 명시적으로 확장한다. token을 HTML이나 설정 파일에 저장하지 않는다.

## 4. 비교 화면의 세부 변경 표시

[비교 서비스](../../src/main/kotlin/io/intenttrace/record/application/RecordComparisonService.kt)는 서로 다른 필드 목록을 반환한다. [비교 화면](../../src/main/kotlin/io/intenttrace/record/adapter/in/browser/RecordBrowserSections.kt)은 각 필드의 전체 원본·후속 내용을 나란히 보여준다. 판단이 여러 개면 어느 판단 한 개가 삭제됐거나 출처만 바뀌었는지 사용자가 직접 찾아야 한다.

현재 전체 내용 보기를 유지하면서 항목별 추가·삭제와 바뀐 텍스트를 강조하고, 변경된 항목만 보는 기능을 추가한다.

완료 기준:

- 판단 문장이 같고 출처만 바뀐 경우도 변경으로 표시한다. 순서 변경과 내용 변경을 구분한다.
- 중복된 판단이나 코드 근거를 임의로 하나의 항목으로 합치지 않는다. 비교 대응이 불명확하면 원본·후속 전체 항목을 보인다.
- 삭제된 코드 근거와 새 검증이 없는 사실을 계속 표시한다. 색상 외에도 추가·삭제·변경 문구로 구분한다.
- 비교를 위해 공개 본문이나 기존 판단의 출처를 바꾸지 않는다. 비공개 후속 기록의 소유권 검사를 유지한다.

## 5. 기록 상태 변경 이력

[기록 변경 서비스](../../src/main/kotlin/io/intenttrace/record/application/ChangeRecordFacade.kt)는 현재 기록을 갱신하고 작업별 횟수를 집계한다. 생성·현재 확인·공개 시각과 게시 시도 이력은 있지만, 초안을 언제 수정했고 확인을 언제 취소했는지 보여주는 별도 이력은 없다. 현재 버전 번호와 집계 지표로는 이를 복원할 수 없다.

기록 ID, 작업 종류, 인증 사용자 subject, 이전·이후 버전과 상태, 처리 시각만 추가 이력으로 남긴다. 초안 본문 복제나 대화 원문 저장은 범위에 넣지 않는다.

완료 기준:

- 성공한 변경과 이력을 같은 DB 트랜잭션에서 저장한다. 버전 충돌·실패·멱등 재시도로 성공 이력이 중복되지 않는다.
- 기록 화면에서 읽을 수 있는 범위를 명시한다. 공개 기록을 읽을 수 있다는 이유로 과거 비공개 작업 이력을 모두 노출하지 않는다.
- 기존 기록의 과거 이력을 추정해서 채우지 않는다. 이력 수집 시작 전 작업은 확인할 수 없다고 표시한다.
- 새 Flyway migration과 PostgreSQL 검증을 포함하고 원문 본문·token·개인 경로를 추가 저장하지 않는다.

## 이번 검토 범위

코드·기준 문서와 Zed 공식 문서를 확인하고, 합성 세션 값과 로컬 응답으로 중계기의 오류 정보 손실을 재현했다. 실제 GitHub 사용자·게시 요청은 사용하지 않았다. 제품 코드·테스트·DB 스키마는 변경하지 않았으며 전체 회귀 테스트도 재실행하지 않았다. 검토 문서와 인수인계 링크만 변경했다.
