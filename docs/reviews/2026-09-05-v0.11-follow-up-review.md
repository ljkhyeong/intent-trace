# IntentTrace 0.11.0 이후 개선 검토

검토일: 2026-09-05

기준 커밋: `ff1c119116b3c382689b8dbc2bbe94e14f7a8ba1`

검토 당시 상태: 코드에서 확인한 불편과 후속 기능 제안. 4개 항목의 0.12.0 구현 결과는 [검증 기록](2026-09-05-v0.12-verification.md)을 따른다.

0.10.0 검토의 5개 항목은 0.11.0에 반영됐다. 이번에는 코드 확인 실패 안내, 웹 목록 필터, 느린 조회의 중단·재개, Zed 설치·배포를 확인했다. 우선순위는 코드와 공식 문서에 근거하며 실제 운영 지연이나 사용자 빈도를 측정한 결과는 아니다.

## 우선순위

| 순서 | 우선순위 | 항목 | 필요한 결과 |
|---|---|---|---|
| 1 | P2 | 개별 코드 근거 확인의 지원 불가 안내 | 용량 제한·일부 트리·지원하지 않는 객체를 연결 장애와 구분한다. |
| 2 | P2 | 웹 목록의 상태·파일·작성자 필터 | 본인의 폐기 기록을 다시 찾고 기존 조회 조건을 웹에서도 사용한다. |
| 3 | P2 | 과거 기록 조회의 전체 시간·호출 수 제한 | 느린 원격 조회를 중단하고 완료하지 못한 후보부터 이어서 확인한다. |
| 4 | P3 | Zed 연결 도구의 배포 패키지와 MCP 레지스트리 등록 준비 | 저장소 전체를 내려받는 설치 절차를 줄이고 버전별 설치·업데이트를 지원한다. |

1·2번을 먼저 반영할 수 있다. 3번은 느린 GitHub 응답을 재현해 제한 값을 정하고, 4번은 배포 대상과 패키지 이름을 정한 뒤 진행한다.

## 1. 개별 코드 근거 확인의 지원 불가 안내

[브라우저 컨트롤러](../../src/main/kotlin/io/intenttrace/record/adapter/in/browser/RecordBrowserController.kt)의 개별 근거 확인은 `RecordEvidenceService`를 호출한다. [지원 불가 예외](../../src/main/kotlin/io/intenttrace/record/application/GitEvidenceReads.kt)는 `GitHubApiException`을 상속한다. 이 예외가 발생하면 현재 브라우저의 공통 처리기가 HTTP 502와 “GitHub 연결을 확인하지 못했습니다. 잠시 후 다시 시도해 주세요.”를 반환한다.

[GitHub 코드 어댑터](../../src/main/kotlin/io/intenttrace/record/adapter/out/github/GitHubGitEvidenceClient.kt)는 크기 제한, 잘린 트리, 지원하지 않는 객체를 구분한다. 같은 객체와 제한으로 재조회해도 해결되지 않는 조건인데 웹에서는 잠시 기다린 뒤 다시 시도하라고 안내한다. 과거 기록 조회는 이미 후보별 사유를 표시하므로 개별 확인 화면에도 같은 구분이 필요하다.

완료 기준:

- `SIZE_LIMIT`, `TRUNCATED_TREE`, `UNSUPPORTED_OBJECT`를 한국어로 설명하고 일시적 연결 장애와 구분한다.
- 확인하지 못한 결과를 코드 불일치나 테스트 실패로 표시하지 않는다. 원래 기록으로 돌아갈 수 있게 한다.
- 인증·권한·호출 제한은 기존 처리를 유지하고 외부 오류 본문을 노출하지 않는다.
- 브라우저 경계에서 지원 불가 예외의 응답과 안내만 필요한 만큼 확인한다.

## 2. 웹 목록의 상태·파일·작성자 필터

[목록 서비스](../../src/main/kotlin/io/intenttrace/record/application/ChangeRecordCatalog.kt)는 상태·파일·팀 작성자 필터를 제공한다. 본인 범위의 기본 목록에서는 폐기 기록을 제외하고, `status=DISCARDED`를 명시하면 조회한다. [웹 검색 화면](../../src/main/kotlin/io/intenttrace/record/adapter/in/browser/RecordBrowserPage.kt)과 컨트롤러는 저장소·검색어·범위·커서만 받는다. 현재 웹에서는 기록 ID를 알고 직접 열 수는 있지만 목록에서 폐기 기록을 선택해 찾을 수 없다.

완료 기준:

- 본인 목록에서 초안·작성자 확인·폐기 상태를 선택한다. 기본 목록에서는 계속 폐기 기록을 제외한다.
- 팀 목록은 공개·대체 상태와 작성자 GitHub 숫자 ID, 파일 경로로 좁힌다. 표시 이름을 소유권 키로 사용하지 않는다.
- 다음 페이지와 로그인 복귀에 조회 조건을 유지하고 조건을 바꾸면 이전 커서를 초기화한다.
- 기존 목록 서비스를 사용해 본인·팀 권한을 유지한다. 폐기 기록의 조회 기능에 복원이나 재편집을 포함하지 않는다.

## 3. 과거 기록 조회의 전체 시간·호출 수 제한

[과거 기록 조회](../../src/main/kotlin/io/intenttrace/record/application/ChangeIntentHistoryService.kt)는 후보를 기본 5개, 최대 20개씩 순차 처리한다. 후보의 근거마다 커밋·트리·blob·조상 관계를 조회할 수 있다. 요청 안의 캐시는 저장 개수를 제한하지만 전체 원격 호출 수나 처리 시간은 제한하지 않는다.

[HTTP 설정](../../src/main/resources/application.properties)의 연결 5초·읽기 10초 제한은 개별 호출에 적용된다. [Zed 중계기](../../clients/zed/bridge.mjs)는 도구 호출에 60초 제한을 둔다. 각 원격 호출이 개별 제한 안에서 끝나더라도 여러 호출의 합계가 클라이언트 제한을 넘을 수 있다. 애플리케이션 조회 루프에는 전체 기한 확인이나 요청 취소 확인이 없다. 실제 운영에서 이 지연이 발생했다는 의미는 아니다.

완료 기준:

- 느린 로컬 GitHub 응답으로 여러 호출의 누적 지연과 취소 동작을 먼저 확인한다.
- 조회 전체의 시간·원격 호출 수 제한을 정하고 다음 호출 전에 남은 범위를 확인한다. 필요하면 개별 호출 제한도 남은 시간에 맞춘다.
- 제한에 도달하면 완료한 결과와 미완료 여부를 구분한다. 미완료 후보를 건너뛰지 않는 재개 위치를 반환하고 같은 후보를 다시 처리해도 결과가 중복되지 않게 한다.
- 인증·권한·호출 제한을 일반 부분 실패로 숨기지 않는다. 클라이언트 취소가 전달되는 경로에서는 후속 원격 호출을 멈춘다.
- REST·MCP·웹이 같은 조회 정책을 사용한다. 변경·게시 요청의 자동 재시도는 추가하지 않는다.

## 4. Zed 연결 도구의 배포 패키지와 MCP 레지스트리 등록 준비

[현재 패키지](../../clients/zed/package.json)는 `private: true`이며 저장소 내부 실행용이다. [Zed 사용 안내](../clients/zed.md)는 저장소에서 의존성을 설치하고 연결 도구의 절대 경로를 설정하도록 안내한다. 저장소나 Node 설치 위치가 바뀌면 다시 등록해야 한다. 여러 사용자에게 배포하려면 버전별 설치 패키지와 업데이트 절차가 필요하다.

Zed 공식 문서는 MCP 서버 확장 플러그인을 폐지하고 공식 MCP 레지스트리로 이동할 계획을 안내한다. 이는 전환 계획이며 현재 사용자 지정 MCP 연결이 중단됐다는 의미는 아니다. 이 방향을 고려하면 배포 가능한 연결 도구와 레지스트리 등록 준비를 우선하는 편이 적절하다. [Zed MCP 확장 공식 문서](https://zed.dev/docs/extensions/mcp-extensions)

완료 기준:

- 필요한 실행 파일만 포함한 버전별 패키지를 만들고 저장소 밖의 빈 폴더에서 설치·설정·연결 점검을 확인한다.
- 버전을 고정해 설치하고 업데이트·제거할 수 있게 한다. 지원 운영체제와 Node 요구 사항을 명시한다.
- `its_` 입력·전달 방식과 비밀값 미저장 규칙을 유지한다. 패키지나 레지스트리 메타데이터에 개인 서버 주소·token을 포함하지 않는다.
- 패키지 이름·배포 위치·레지스트리의 현재 등록 요구 사항을 확인해 제출 자료를 준비한다. 실제 외부 배포와 등록은 배포 대상으로 정한 계정·저장소에서 수행한다.
- 패키지 배포, 실제 Zed 앱 연결, 편집기 인라인 기능의 지원 범위를 각각 명시한다.

## 이번 검토 범위

관련 코드·기준 문서와 Zed 공식 문서를 확인했다. 이번 검토에서는 새 실행 재현이나 전체 회귀 테스트를 수행하지 않았다. 제품 코드·테스트·DB 스키마는 변경하지 않고 검토 문서와 인수인계 링크만 추가했다. 0.11.0에서 이미 실행한 검증은 [검증 기록](2026-09-05-v0.11-verification.md)을 따른다.
