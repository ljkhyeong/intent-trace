# IntentTrace 0.12.0 구현·검증 기록

검증일: 2026-09-05

범위: [0.11.0 후속 검토](2026-09-05-v0.11-follow-up-review.md)의 4개 항목. Zed는 설치 파일과 등록 자료 생성까지 포함하며 외부 게시는 포함하지 않는다.

## 구현

| 항목 | 반영한 내용 |
|---|---|
| 개별 코드 확인 불가 | HTTP 422와 용량·트리·객체 사유, 코드 일치 미확인 안내, 원래 기록 링크 |
| 웹 목록 필터 | 상태·파일·팀 작성자 ID, 본인 폐기 기록, 로그인·다음 페이지 조건 유지, 새 검색과 범위 전환의 커서 초기화 |
| 조회 중단·재개 | 기본 30초·코드 HTTP 40회, 남은 기한을 적용한 원격 호출, interrupt 확인, 근거 순서를 담은 재개 커서 |
| Zed 설치·등록 자료 | 의존성이 포함된 버전별 패키지·SHA-256, 설치 명령, `launch`, 서버 주소 환경 변수, 공개 제출용 이름·`mcpName`·`server.json` 생성 |

기존 공개 본문·근거 순서를 유지하며 REST·MCP·웹은 같은 history 서비스를 사용한다. 중단 뒤에는 반환되지 않은 근거를 추가하고, 지원 불가 기록의 ID 재조회는 같은 후보의 이전 결과를 교체한다. 이 차이를 PRD·ADR·사용 스킬에 반영했다.

서버 검증은 Java 21, 패키지 검증은 macOS의 Node.js 25.4.0에서 실행했다. CI는 기존 Node 22·Ubuntu 작업에서 같은 패키지 테스트를 실행하도록 구성되어 있다. 이번 작업에서 원격 CI 실행 결과를 확인한 것은 아니다.

## 실패·재개 경계

- 실제 로컬 HTTP 서버에서 코드 호출을 1회로 제한했을 때 커밋 다음의 트리 호출이 발생하지 않는 것을 확인했다.
- 각 응답을 200ms 지연시키고 전체 기한을 350ms로 정했을 때 `TIME_LIMIT`으로 중단하고 2초 이내에 반환하는 것을 확인했다.
- 실행 스레드에 interrupt가 전달된 상태에서는 `CANCELLED`로 중단하고 추가 HTTP 호출을 하지 않았다.
- 통합 테스트에서 한 기록의 BASE 근거 결과를 반환한 뒤 중단을 발생시켰다. 재개 결과에는 아직 반환하지 않은 TARGET 근거만 포함됐고 다음 후보 페이지도 이어서 조회됐다.
- 다른 조회 조건의 재개 커서와 다른 저장소 기록으로 만든 커서는 거부됐다. 기존 인증·권한·호출 제한 실패를 전체 요청 실패로 처리하는 검증도 통과했다.
- 실제 인증 MCP 요청에서 history의 선택 입력을 생략하고 `complete=true`, `stopReason=null` 응답을 확인했다. 실제 Spring 서버와 stdio SDK 중계기의 초기화·도구 목록·진단 호출도 통과했다.

## 설치 파일

`node scripts/package-zed.mjs`로 `build/zed-release/intent-trace-zed-0.12.0.tgz`와 SHA-256 파일을 생성했다. 확인한 파일은 3,313,097바이트다. archive에 심볼릭 링크나 개인 절대 경로의 항목·링크 대상은 없었다.

임시 폴더와 빈 npm 캐시에서 오프라인 설치한 뒤 설치된 실행 명령으로 설정을 생성·저장하고 MCP 연결을 확인했다. `launch`는 임시 Zed 대역 프로그램에 세션과 공백이 있는 인자를 전달했다. token이 설정·연결 출력에 나오지 않는 것을 확인했다.

`--npm-name`, `--mcp-name`, `--repository`에 예시 계정 값을 넣어 `build/zed-registry-preview/server.json`을 만들고 공식 JSON 스키마를 통과했다. 실제 npm 소유권·계정 인증·레지스트리의 원격 패키지 확인과 등록은 수행하지 않았다. 기본 설치 패키지는 `private: true`로 유지한다.

## 화면과 검증 범위

브라우저 확인은 서버 통합 테스트가 생성한 실제 HTML과 CSS를 로컬에서 열어 진행했다. 모바일 검색·조회 중단 화면의 가로 너비는 390px로 viewport를 넘지 않았다. 스크린샷은 `output/playwright/v12-*.png`에 남겼다. 로그인·검색 조건·페이지 이동·권한 검사는 서버 통합 테스트 범위이며, 실제 GitHub 계정으로 브라우저 로그인을 완료한 검증은 아니다.

JDBC·Flyway·backup·restore는 변경하지 않아 이번 버전에서 PostgreSQL 별도 검증은 재실행하지 않았다. 직전 PostgreSQL 17 검증은 [0.11.0 기록](2026-09-05-v0.11-verification.md)을 따른다. 실제 Zed 앱과 GitHub 사용자 승인·게시도 이번 버전에서 다시 확인하지 않았다.

조회 기한은 코드 확인 작업을 제한한다. 외부 사용자 인증과 모든 HTTP 응답의 전체 시간을 보장하지 않으며, 모든 클라이언트의 연결 종료가 서버 interrupt로 즉시 전달되는 것도 아니다. 전달되지 않은 취소는 서버의 조회 기한으로 제한한다.
