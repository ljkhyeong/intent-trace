# IntentTrace 0.12.1 검증 기록

검증일: 2026-09-05

작업 전 기준: `a6c37cf` · [0.12.0 후속 개선 검토](2026-09-05-v0.12-follow-up-review.md)의 세 항목을 반영했다.

## 변경 내용

| 항목 | 변경 후 동작 |
|---|---|
| Zed 세션 입력 | 숨긴 입력을 제공하지 못하면 표준 입력 대체 전에 중단한다. EOF·입력 취소도 실행하지 않고 한국어 안내로 끝낸다. 환경 변수 실행은 유지한다. |
| 배포 의존성 | 작업 폴더의 `node_modules`를 복사하지 않는다. 임시 폴더에서 잠금 파일로 운영 의존성을 설치하고 설치 스크립트는 실행하지 않는다. |
| 배포 기준 기록 | 패키지 안의 `build-info.json`과 옆의 `.build.json`에 버전·잠금 파일 해시를 기록한다. 옆 파일에는 압축 파일 해시도 담는다. |
| 조회 제한 | 근거 하나의 최대 호출 수를 고려해 서버 설정을 7~200회로 제한한다. 기본값 30초·40회는 유지한다. |
| 진행하지 못하는 재개 | 첫 미완료 근거도 끝내지 못하고 시간·호출 제한에 도달하면 `resumeBlocked=true`다. 같은 커서를 보존하고 원인 확인 뒤 수동 재조회를 안내한다. |

REST·MCP는 같은 조회 서비스를 사용한다. 근거 중간 응답이나 사용자 자격 증명을 요청 사이에 새로 저장하지 않는다. 공개 기록·DB 스키마·JDBC·backup·restore는 변경하지 않았다.

### 입력·설치 확인 범위

- 제어 터미널이 없는 새 프로세스에 합성 `its_`를 제공했을 때 실패 종료하고 Zed 대역이 실행되지 않았다. 세션 값과 traceback도 출력되지 않았다.
- 정상 입력과 미리 주입한 환경 변수의 세션·공백이 있는 실행 인자 전달을 확인했다. EOF·취소는 대역으로 발생시켜 실행하지 않는 것을 확인했다.
- 임시 프로젝트의 직접 의존성 SDK와 하위 의존성 zod를 99.0.0으로 만들어 두었다. 생성한 패키지에 설치된 모든 운영 의존성의 버전은 잠금 파일과 같았고 임시 개발 폴더의 99.0.0 값은 바뀌지 않았다.
- 선언과 잠금 파일이 다른 경우 생성 명령이 실패하고 새 출력 폴더가 만들어지지 않았다.
- 빈 npm 캐시와 저장소 밖 폴더에서 오프라인 설치·설정 생성·등록·표준 MCP 연결·Zed 실행 환경 전달을 확인했다. 실제 Spring 서버와 stdio 중계기 통합 테스트도 통과했다.

### 조회 확인 범위

- 1·6·201회 정책 설정을 거부했다. 7회 제한에서는 하나의 근거를 처리한 뒤 멈추고, 같은 기록의 다음 근거를 재개해 중복 없이 반환했다. 이 통합 테스트의 Git 대역은 실제 어댑터와 같은 커밋·트리·조상·blob 호출 수를 차감한다.
- 첫 근거 반환 후 다음 근거에서 기한 중단을 발생시켰다. 같은 커서로 두 번 재개해도 그 근거가 중단되면 `resumeBlocked=true`, 빈 결과와 같은 커서를 반환했다. 중단 원인을 제거한 뒤에는 나머지 근거와 다음 후보를 정상 조회했다. 이 반복 시나리오의 기한 중단은 Git 대역에서 발생시켰다.
- 실제 로컬 HTTP 지연 테스트로 원격 호출의 전체 기한·호출 수·interrupt 후 추가 호출 중단을 확인했다. 실제 GitHub 지연 상황 전체를 재현한 것은 아니다.
- 웹의 원인 확인 안내·수동 재조회 링크와 기존 권한 검사를 확인했다. 인증된 MCP 응답에서도 새 `resumeBlocked` 필드를 확인했다.

## 실행하지 않은 범위

실제 Zed 앱, 실제 GitHub 사용자 승인·PR 게시, npm 게시·MCP 레지스트리 등록은 수행하지 않았다. 예시 계정의 등록 자료 생성만 패키지 테스트에 포함했다. DB 관련 변경이 없어 별도 PostgreSQL 검증을 재실행하지 않았다. 웹 안내는 서버 통합 테스트로 확인했으며 이번 수정에서 실제 브라우저 화면 검사는 추가로 실행하지 않았다.
