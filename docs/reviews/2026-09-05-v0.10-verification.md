# IntentTrace 0.10.0 구현·검증 기록

확인일: 2026-09-05

## 반영한 변경

| 항목 | 결과 |
|---|---|
| 설치 token 제거 | 서버와 로컬 실행 도구가 점 두 개를 포함하는 `ghs_` token 전체를 제거하고 문장 끝을 보존한다. |
| 중복 조회 | 같은 인증 요청 안의 저장소 권한과 history 후보 간 Git 객체를 재사용한다. 새 요청은 권한을 다시 확인한다. |
| 일부 실패 | 지원 불가 후보를 `failures`에 표시하고 `retryRecordId`로 다시 조회한다. 인증·권한·호출 제한은 전체 요청을 중단한다. |
| 게시 사전 점검 | 관리자만 App 키·인증·설치·실제 token 발급 범위와 권한을 확인한다. Check Run은 만들지 않는다. |
| 원본 비교 | REST·MCP·브라우저에서 판단·출처·근거·검증·질문과 커밋·스냅샷을 비교한다. |
| 브라우저 | PR 기록·현재 커밋 일치·게시 결과 미확인과 연결 진단 화면을 제공한다. |
| Zed | JSONC 미리보기·등록·업데이트와 실제 앱의 승인·조회·세션 폐기 후 재연결을 확인했다. |

## 자동 검증

- `./gradlew test`: 85개 중 84개 통과, PostgreSQL 전용 1개 제외. 실제 Spring 서버와 stdio 중계 SDK 통합 테스트를 포함한다.
- `npm ci --prefix clients/zed --ignore-scripts`, `npm test --prefix clients/zed`: 재설치 후 5개 통과.
- `scripts/validate-plugin.sh`와 두 스킬의 `quick_validate.py`: 통과.
- 간접 의존성 `qs`를 호환 수정 버전으로 갱신했다. 재설치 시 의존성 감사 결과 알려진 취약점은 0개였다.
- DB 스키마·JDBC·backup/restore를 변경하지 않아 별도 PostgreSQL 검증은 재실행하지 않았다.

## 실제 앱 확인

공식 배포 Zed 1.18.1의 서명을 확인하고 임시 사용자 데이터와 프로젝트에서 실행했다. 사용자 설정 파일을 변경하지 않았다. 실제 IntentTrace Spring 서버와 메모리 DB를 사용하되 GitHub 응답과 모델의 도구 호출 요청만 로컬 stub으로 대체했다.

1. 등록 도구가 만든 설정을 Zed가 읽고 MCP 연결을 활성 상태로 표시했다.
2. Agent의 `list_change_records` 승인 화면에서 대상 저장소 인자를 확인하고 한 번 허용했다.
3. 실제 IntentTrace 서버에 만든 공개 기록의 ID·제목·상태가 Zed에 반환됐다.
4. 테스트 세션을 폐기한 후 같은 조회가 비밀값 없는 연결 오류로 표시됐다.
5. 새 세션을 환경 변수로 전달해 Zed를 재실행한 뒤 같은 기록이 다시 반환됐다.

실제 GitHub 사용자 승인·유료 모델·원격 저장소 쓰기는 수행하지 않았다. 시간 경과 만료 대신 명시적 세션 폐기로 인증 실패를 확인했다. 인라인 IDE 기능과 자동 기록 수집은 제공하지 않는다.

브라우저에서는 원본 비교와 연결 진단을 390px 너비에서 확인했다. 원본과 후속의 제목·근거·검증 누락 안내를 읽을 수 있으며 가로 넘침이 없었다. 로그인 복귀, 다른 작성자의 비공개 비교 차단, PR 게시 결과 미확인은 서버 통합 테스트로 확인했다.

## 남아 있는 범위

고정 게시 token의 원격 권한 확인, 요청 간 권한 캐시, webhook 무효화, 대용량 Git 객체, 실제 사용량에 따른 지연 시간 측정은 이번 변경에 포함하지 않았다. 게시 사전 점검 성공은 이후 PR HEAD·권한 변경에 따른 실제 게시 성공을 보장하지 않는다.
