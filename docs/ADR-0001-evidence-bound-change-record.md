# ADR-0001: 변경 의도 기록을 불변 코드 증거에 묶는다

## 상태

채택

## 배경

변경 의도 설명이 현재 작업 트리만 가리키면 코드가 바뀐 뒤에도 예전 설명과 테스트가 최신인 것처럼 보일 수 있습니다. 또한 소스 코드만 보고 작성자의 목적을 확정하면 AI의 추론이 사실로 섞입니다.

## 결정

- 공개 기록은 전체 Git 커밋 ID와 저장소 트리의 SHA-256 스냅샷을 가진다.
- 스냅샷 helper는 `git -c core.quotePath=true ls-tree -r --full-tree`의 기존 줄바꿈 출력을 해싱한다. 개인 파일명 표시 설정의 영향을 제거하고 기본 설정으로 만든 기존 해시를 유지한다. `-z` 형식으로 일괄 전환하거나 저장된 해시를 다시 쓰지 않는다.
- 이전 `core.quotePath=false` 해시는 당시 전체 커밋과 같은 출력 설정으로만 재현한다. README의 호환 명령 결과가 저장값과 일치할 때만 해당 기록에 사용하며, 서버의 스냅샷 일치 검사를 완화하지 않는다.
- 코드 근거는 상대 경로, 최소 연속 줄 범위, 해당 내용의 SHA-256을 가진다. JDK `Path.normalize()`의 경로 요소를 `/`로 연결해 서버 운영체제와 관계없이 같은 저장소 경로를 사용한다.
- 검증은 명령, 종료 코드, 시간, 대상 스냅샷, 출력 해시, 짧은 요약을 가진다.
- 검증 시작·종료 시각은 JDK `Instant.plusNanos(500).truncatedTo(MICROS)`로 DB와 같은 마이크로초 정밀도에 맞춘 뒤 멱등 비교와 저장에 사용한다. 기존 DB 기록의 시각을 소급 변경하지 않는다.
- 판단 출처는 사용자 명시, 커밋 명시, 작성자가 확인한 AI 요약, 추론, 미확인으로 구분한다.
- 초안은 작성자가 확인하기 전 공개하지 않는다.
- 공개 기록의 본문은 수정하지 않고 새 공개 기록으로 대체한다.
- REST 대체 API와 MCP `supersede_change_record`는 같은 애플리케이션 서비스를 호출한다. MCP 어댑터에 작성자·상태·버전 검사를 복제하지 않는다.
- 대체할 두 기록은 같은 DB 트랜잭션에서 ID 순서로 행 잠금을 얻은 뒤 최신 상태로 대체 가능 여부를 판단한다. GitHub 권한 조회는 잠금을 얻기 전에 수행한다.
- 원문 대화, 숨은 추론, 검증 원문 출력은 저장하지 않는다.
- 제목·요약·판단·코드 심벌 이름(`symbolName`)·검증·남은 질문을 저장하기 전에 GitHub·IntentTrace token, Bearer 자격 증명, client secret, private key와 개인 home 절대 경로를 제거한다.
- 비밀값 제거 직후 최종 문자열의 길이를 확인한다. 저장 한도를 넘으면 원문 없이 입력 오류를 반환하고, 기록의 일부를 임의로 잘라 저장하지 않는다.
- 코드 근거 helper는 해당 커밋의 객체가 `blob`이고 요청한 끝 줄까지 실제 내용이 있을 때만 해시를 만든다. 객체 존재 여부만으로 디렉터리(`tree`)를 파일로 인정하지 않는다.

## 영향

- 코드가 바뀌면 기존 검증을 현재 검증으로 재사용할 수 없다.
- 초안 생성과 공개 사이에 작성자 확인 단계가 추가된다.
- 팀원은 설명의 출처와 검증 범위를 판단할 수 있다.
- MVP는 Git 객체를 서버에서 직접 읽지 않으므로 제공 스크립트와 클라이언트를 신뢰한다. GitHub 어댑터 단계에서 서버 측 재검증을 추가해야 한다.

## Hope에서 참고한 패턴

Hope 플러그인의 커밋·diff 리뷰 방식에서 다음 패턴만 가져왔다.

- 분석 대상을 전체 커밋과 부모에 고정한다.
- 주장마다 작은 연속 코드 범위를 근거로 연결한다.
- 목적을 명시·추론·미확인으로 구분한다.
- 대상이 바뀌면 기존 결과를 오래된 것으로 취급한다.
- 검증 후 새 산출물을 게시하고 기존 공개 산출물을 덮어쓰지 않는다.

HTML 리뷰 UI와 Hope 고유 산출물 형식은 MVP 범위에 포함하지 않았다.
